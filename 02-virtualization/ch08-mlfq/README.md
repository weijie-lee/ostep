# 第 8 章 Multi-level Feedback Queue

调度器不知道作业要跑多久。规则是：高优先级先跑；同一级轮转；新作业进最高级；在某一级用完配额就降级；每 250 个时间单位全体升回最高级。

参数：三级队列，时间片都是 10，配额是 40 / 40 / 不限。计算型作业一次要 400 个 CPU 时间。交互型作业重复 20 次“算 1、等 I/O 9”。

## 实验步骤

1. 运行：

```bash
python3 02-virtualization/ch08-mlfq/mlfq.py
```

2. 看两个作业在三级队列上各花了多少 CPU 时间。交互型作业的后两级应当是 0。

## 实验结果

```text
模拟结束于 t=420，每 250 个时间单位全体升回最高级
各级时间片 [10, 10, 10]，配额 40/40/不限
  计算型: 完成于 420，各级 CPU 时间 [80, 80, 240]
  交互型: 完成于 228，各级 CPU 时间 [20, 0, 0]
通过：没人告诉调度器作业类型，配额和 I/O 行为把它们分开了
```

## 结果说明

交互型作业总共只用 20 个 CPU 时间，低于最高级配额 40，所以 20 个时间片全部留在最高级，完成于 t=228。计算型作业在最高级用满 40 后降级，升回最高级后又用满一轮，两级各 80，剩下 240 在最低级，完成于 t=420。没有人给作业贴“交互”或“计算”的标签。
