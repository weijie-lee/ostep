# 第 32 章 Concurrency Bugs

三组对照：原子性违反、顺序违反、死锁交错。死锁那组用 `trylock`，程序不会挂住。

## 实验步骤

1. 运行：

```bash
make
./build/03-concurrency/ch32-concurrency-bugs/bugs
```

2. 核对六个数：无锁余额 -100，加锁余额 0，过早读取到 0，先写后读得到 42，两把 `trylock` 都失败。

## 实验结果

```text
原子性违反：两边都通过了余额检查，balance=-100
检查和扣款放进同一把锁，balance=0
顺序违反：读者看到的 value=0（写者还没赋值）
先写后读：value=42
死锁交错：A 握着锁 1 再试锁 2 失败，B 握着锁 2 再试锁 1 失败
通过：trylock 打破持有并等待；若真的阻塞等待，这两条线程会循环等待
```

## 结果说明

余额从 100 开始。两个线程都在对方扣款之前看到“够 100”，两个决定都成立，各扣 100，结果是 -100。同一把锁把检查和扣款包在一起后，只有一个线程成功，余额是 0。读者被屏障挡在写者赋值之前，所以看到初值 0；先写再读才是 42。A 拿着锁 1、B 拿着锁 2 时，彼此的 `trylock` 都失败。如果这里换成阻塞的 `lock`，两个人会循环等待。
