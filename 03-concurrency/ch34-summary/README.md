# 第 34 章 小结（并发）

把这一部分的判断收成四条，并用锁的名字核对“按固定顺序加锁”具体是什么顺序。

## 实验步骤

1. 运行：

```bash
python3 03-concurrency/ch34-summary/summary.py
```

2. 对照第 26 章的 `shared=1/2`、第 30 章的 `while`、第 32 章的 `trylock` 失败。

## 实验结果

```text
并发
  共享可变状态必须放进临界区，否则读改写会丢更新
  Mesa 管程里，被叫醒不等于条件仍成立，等待要用 while
  死锁要四条同时成立：互斥、持有并等待、不可抢占、循环等待
  打破其中一条即可。按固定顺序加锁打破的是循环等待
  两把锁的全局顺序：m1 -> m2
通过
```

## 结果说明

`m1 -> m2` 是把锁名排序后的全局顺序。两个线程都按这个顺序申请，就组不出“A 等 B、B 等 A”的环。第 32 章已经看到相反顺序会让两边的 `trylock` 同时失败。
