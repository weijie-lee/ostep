# 第 42 章 FSCK and Journaling

原地数据一开始是空的。打算写入的事务是：位图 `[True, False]`，指针 0，数据 `NEW`。分别在提交前、提交后崩溃，再用 fsck 处理一个只有悬空指针、没有新数据的盘。

## 实验步骤

1. 运行：

```bash
python3 04-persistence/ch42-journaling/journal.py
```

2. 三个结果要同时成立：没提交则数据仍是空；提交了则重做得到 `NEW`；fsck 把位图改对，但数据仍是空字节。

## 实验结果

```text
未提交就崩溃：数据仍是 b''，指针 None
提交之后崩溃：重做得到数据 b'NEW'，位图 [True, False]
fsck：把悬空指针标成已分配，位图变成 [True, False]，数据仍是 b''
通过：日志知道新值；fsck 只知道结构合不合理
```

重做跑两次，数据仍是 `b'NEW'`。

## 结果说明

没有提交记录时，恢复不去碰原地数据，避免把写了一半的事务装上去。有提交记录时，把日志里的位图、指针和数据再写一次；再写一次结果相同，所以重做是幂等的。fsck 只能看出“指针指向的块在位图里是空的”，于是把那一位置上，它不知道这块本应是 `NEW`。
