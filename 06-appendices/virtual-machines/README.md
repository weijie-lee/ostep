# 附录：虚拟机

客户机执行关中断，再执行开中断。监视器只改客户机自己的中断标志。

## 实验步骤

1. 运行：

```bash
python3 06-appendices/virtual-machines/vmm.py
```

2. 核对：客户机在 `cli` 之后认为中断已关；宿主机的中断标志一直是真；两次敏感指令造成 2 次陷入。打印出来的“陷入次数 1”是 `cli` 刚执行完的时刻，`sti` 之后总数才是 2。

## 实验结果

```text
客户机认为中断已关：True
宿主机中断仍然开着：True，陷入次数 1
通过：客户机看到的是虚拟的控制寄存器
```

程序结束时客户机中断标志恢复为真，陷入次数是 2。这两项由程序里的检查保证，没有单独再打印一行。

## 结果说明

`guest_cli` 把 `guest_interrupts` 设成假，没有碰 `host_interrupts`。客户机以为自己关掉了中断，宿主机的中断仍然开着。这就是陷入并模拟：敏感指令不直接作用于真机器。
